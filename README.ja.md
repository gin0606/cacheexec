# cacheexec

[English](README.md)

macOSとLinuxで、非対話コマンドの標準出力・標準エラー・終了コードをキャッシュします。

```sh
cargo install --path . --locked
cacheexec --ttl 5m -- curl -fsS https://example.com/status
cacheexec --ttl 5m --include-codes 0,1 -- sh -c './condition-check.sh'
cacheexec --ttl 5m --key "$DEPLOY_ENV" --refresh -- ./query
```

コマンドは**必ず `--` の後に指定**します。引数はシェルで解釈せず、そのまま実行します。
パイプ、リダイレクト、変数展開などが必要な場合は、明示的に `sh -c` を使ってください。
子プロセスは呼び出し元の環境を継承し、標準入力を閉じた状態で実行します。
実行中は標準出力と標準エラーを随時転送します。キャッシュが使える場合は実行を省略し、
保存した各バイト列と元の終了コードを返します。非UTF-8のバイト列も保持します。
再生時の出力タイミングや、標準出力と標準エラーの間の順序は保証しません。
キャッシュのヒット・ミスを示すログは出力に追加しません。

コマンド実行には `--ttl` が必須です。`500ms`、`30s`、`5m`、`1h` などの期間を指定できます。
経過時間は実行完了時から計測し、**経過時間がTTL以下**の結果を再利用できます。
`0s` は事実上、新しい実行を要求します。現在時刻が完了時刻より前の場合、その結果は再利用しません。
TTLを変更してもキャッシュキーは変わりません。

既定では、通常終了したすべての終了コード（0〜255）を保存します。
`--include-codes 0,1` は指定したコードだけを保存・再利用し、`--exclude-codes 2,3` は
指定したコードを除外します。この2つのオプションは併用できません。
既存の結果にも、呼び出しごとに指定した条件を適用します。
起動失敗やシグナルによる終了は保存しません。`--refresh` は以前の結果を無効にしてから
再実行します。更新結果が保存対象外になった場合や、実行が失敗・中断した場合も、
以前の結果には戻りません。コマンドを自動で再試行することはありません。

キーには、コマンドと各引数の境界を保持した値、作業ディレクトリ、任意の `--key` を含めます。
環境変数、実行ファイルの内容、入力ファイルの内容の変化は**自動検知しません**。
これらが変わる場合は、追加キーやrefreshを使ってください。

保存先は両OSとも `$XDG_CACHE_HOME/cacheexec` です。XDGが未設定または空の場合は
`$HOME/.cache/cacheexec` を使います。`--cache-dir PATH` で変更できます。
ローカルファイルに保存し、完了した結果にはチェックサムを付け、不可分に公開します。
キーごとに最新の結果を1件保持します。出力はメモリに蓄えるため、利用可能なメモリに
収まる出力量を想定してください。ネットワークファイルシステムでの動作保証、
対話コマンド、PTYは対象外です。

結果が存在しない場合は通常のキャッシュミスです。破損やアクセス不能はrefresh時も含めて
ツール自体のエラーとし、黙ってキャッシュを迂回しません。
ツールエラーは標準エラーに `cacheexec:` で始まる診断を出し、**125**で終了します。
引数エラーの終了コードは**2**です。子プロセスが通常終了した場合は、その終了コードを
そのまま返します（2や125も含みます）。内部エラーとの区別には診断を使ってください。
子プロセスがシグナルで終了した場合は、**128 + シグナル番号**を返します。
実行後の保存に失敗した場合、子プロセスがすでに終了していることと終了コードを診断に含めます。
その場合もコマンドを再実行しません。

同じキーへの同時呼び出しは、1つの実行を共有します。`--refresh` や、TTL・終了コードの
選択条件が異なる呼び出しも合流します。実行担当には出力を随時転送し、待機者には完了後に
標準出力・標準エラーの全内容と終了結果を返します。待機者自身の条件がその終了コードを
除外していても、今回の実行結果は受け取れます。参加者のうち誰かがその通常終了コードの
保存を許可していれば、後続の条件を満たす呼び出し向けに保存します。
全員が保存を許可しない場合は、既存の待機者のためだけに一時保持します。
各待機者は自分が参加した実行世代を保持するため、後の実行に結果を上書きされません。
異なるキーは独立して実行します。進行中のrefreshは、以前の保存結果より優先されます。

実行担当に送られたSIGINT/SIGTERMは、子プロセスグループへ転送します。
全参加者に128 + シグナル番号を返し、結果は保存しません。子がシグナルを処理して
通常終了した場合も同じです。待機者だけに送られたシグナルは、その待機だけを
128 + シグナル番号で終了させ、共有実行は継続します。完了済み結果の再生中や、
出力の受け取り側が読み取りを止めた場合にも適用します。
出力の配送を中断すると、その呼び出しの出力や診断が途中で切れることがあります。
子プロセスのタイムアウトは設けません。これらのシグナルを無視する子は実行を続ける場合があります。
子プロセスグループから離れた子孫へのシグナル伝播は保証しません。

実行担当が突然終了した場合（SIGKILLを含む）、待機者はツールエラーを返し、再試行しません。
実行担当の識別にはカーネルのロックを使い、PIDの再利用を確認する方式には依存しません。
後続の呼び出しは新しい実行を開始できます。ただし、SIGKILLで親を失った子はまだ動いている
可能性があり、自動では終了させません。共有用の一時結果は完了時にファイル名を削除しますが、
既存の待機者は開いたファイル記述子を通じて引き続きアクセスできます。
取り残された実行マーカーは、次の同一キーの呼び出しが回収します。
呼び出しの実行中にロックファイルを削除・置換しないでください。
ファイルシステムやロックの故障は明示的なエラーになります。削除には以下のオプションを使ってください。

## 明示的なキャッシュ削除

```sh
cacheexec --cache-dir ./cache --clear
cacheexec --cache-dir ./cache --clear --older-than 24h
```

削除時にはコマンドやTTLを指定しません。`--clear` は使用中でない再利用可能な結果をすべて削除します。
`--older-than` を付けると、完了からの経過時間が指定期間を厳密に超えた結果だけを削除します。
境界と一致する結果や未来の完了時刻を持つ結果は残します。この期間は読み手のTTLとは独立しています。
走査は1回だけなので、同時に作成されたキーは次回の削除まで残る場合があります。
自動削除やバックグラウンドサービスはありません。

結果の要約には、削除した結果数、回収した実行マーカー数、使用中でスキップしたキー数、
失敗数を表示します。使用中のキーのスキップは成功扱いです。必要に応じて後で再度削除してください。
実行中のデータと待機者へ未配送の実行世代は、refreshや新しい実行をまたいでも保護します。
保存先ディレクトリが存在しなければ、作成せずに成功します。
破損、権限不足、削除失敗は診断と途中までの件数を示し、125で終了します。
成功した削除は取り消しません。破損した結果は調査のため残します。
同時呼び出しが別々のロックinodeを使うことを防ぐため、固定の `.lock` ファイルは意図的に残します。
保存用の匿名一時ファイルや認識できないファイルも、所有者を安全に特定できないため残します。
こうした残存ファイルを手動で削除する場合は、すべてのcacheexec呼び出しが停止してから行ってください。
呼び出しの実行中にキャッシュディレクトリを再帰的に削除しないでください。

条件判定スクリプトには、次のように指定します。

```sh
cacheexec --ttl 5m --include-codes 0,1 -- sh -c './condition-check.sh'
```

終了コード0と1は再利用し、それ以外のコードは再実行して標準エラーとともに毎回返します。
cacheexec自体は終了コードにアプリケーション上の意味を付けません。
保存結果を削除すると、次の呼び出しでスクリプトを再実行します。

## 開発

`rust-toolchain.toml` でRust 1.98.0を固定しています。macOS/LinuxのCIでも同じチェックを実行します。

```sh
cargo fmt --check
cargo clippy --locked --all-targets -- -D warnings
cargo test --locked
```
