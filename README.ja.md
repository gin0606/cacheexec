# cacheexec

[English](README.md)

macOSとLinuxで、非対話コマンドの標準出力・標準エラー・終了コードをキャッシュします。

cacheexecは、APIへの問い合わせ、条件判定、ビルドやデプロイの補助スクリプトなど、実行コストが高いコマンドや毎回の実行が不要なコマンドの結果を再利用するための小さなツールです。コマンドを直接実行して出力と終了結果を保存し、保存結果が再利用できる間は実行を省略します。

## インストール

開発時は、ローカルのソースツリーからcacheexecをインストールします。

```sh
cargo install --path . --locked
```

配布方法と一般利用者向けのインストール手順は、まだ確定していません。

## クイックスタート

```sh
cacheexec --ttl 5m --include-codes 0 -- curl -fsS https://example.com/status
cacheexec --ttl 5m --include-codes 0,1 -- sh -c './condition-check.sh'
cacheexec --ttl 5m --key "$DEPLOY_ENV" --refresh -- ./query
```

保存結果が再利用できる間に同じ呼び出しを行うと、コマンドを実行せず、保存した出力と終了コードを再生します。

## 重要な挙動

- **既定では非ゼロの終了コードも保存します。** 一時的な失敗を再利用したくない場合は、`--include-codes 0` を指定してください。
- コマンドは**必ず `--` の後に指定**します。シェルで解釈せず直接実行するため、パイプ、リダイレクト、変数展開などが必要な場合は明示的に `sh -c` を使ってください。
- キーには、コマンド、各引数の境界を保持した値、作業ディレクトリ、任意の `--key` を含めます。環境変数、実行ファイルの内容、入力ファイルの内容は自動で追跡しません。
- 子プロセスは呼び出し元の環境を継承しますが、標準入力は閉じた状態で実行します。対話コマンドとPTYは対象外です。
- 出力はメモリに蓄えます。再生時も各バイトは保持しますが、出力タイミングや標準出力と標準エラーの間の順序は保証しません。

## コマンド実行と出力

子プロセスの実行中は、標準出力と標準エラーを随時転送します。キャッシュが使える場合は実行を省略し、保存した各バイト列と元の終了コードを返します。非UTF-8のバイト列も保持します。再生時の出力タイミングや、標準出力と標準エラーの間の順序は保証しません。`--verbose` を指定した場合だけ、キャッシュ動作の診断を追加します。

コマンドを自動で再試行することはありません。起動失敗やシグナルによる終了は保存しません。

## TTL・終了コード選択・refresh

コマンド実行には `--ttl` が必須です。`500ms`、`30s`、`5m`、`1h` などの期間を指定できます。経過時間は実行完了時から計測し、**経過時間がTTL以下**の結果を再利用できます。`0s` は事実上、新しい実行を要求します。現在時刻が完了時刻より前の場合、その結果は再利用しません。TTLを変更してもキャッシュキーは変わりません。

既定では、通常終了したすべての終了コード（0〜255）を保存します。`--include-codes 0,1` は指定したコードだけを保存・再利用し、`--exclude-codes 2,3` は指定したコードを除外します。この2つのオプションは併用できません。既存の結果にも、呼び出しごとに指定した条件を適用します。

`--refresh` は以前の結果を無効にしてから再実行します。更新結果が保存対象外になった場合や、実行が失敗・中断した場合も、以前の結果には戻りません。

条件判定スクリプトには、次のように指定します。

```sh
cacheexec --ttl 5m --include-codes 0,1 -- sh -c './condition-check.sh'
```

終了コード0と1は再利用し、それ以外のコードは再実行して標準エラーとともに毎回返します。cacheexec自体は終了コードにアプリケーション上の意味を付けません。保存結果を削除すると、次の呼び出しでスクリプトを再実行します。

## キャッシュ動作の確認

```sh
cacheexec --ttl 5m --verbose -- ./query
```

`--verbose` は、人向けの診断を**標準エラー**に追加します。各診断は `cacheexec: verbose:` で始まります。以下は表示例です（文言や期間の表示形式は変更され得ます）。

```text
cacheexec: verbose: run reason=missing ttl=5m key=… cache-dir="/…/cacheexec"
cacheexec: verbose: completed exit=0 saved=yes
```

動作の決定時に、完了を待たずに表示を試みます。`hit` は保存結果の再利用、`run` は新規実行、`join` は進行中の同一キー実行への合流です。進行中の実行があれば、TTL・終了コード条件・refreshにかかわらず合流します。再実行理由は `refresh`（明示更新）、`missing`（結果なし）、`future-timestamp`（未来の完了時刻）、`expired`（TTL超過）、`policy`（終了コード条件不適合）の優先順で表示します。適用TTL、キーのハッシュ、保存先の絶対パスも表示します。保存結果を評価した場合の `age` は完了からの秒数で、未来時刻の場合は負になります。

完了時には終了結果と、その実行世代の保存状況を表示します。`reason=participant-policy` は参加者全員の条件で保存対象外、`reason=reused` はhitによる再利用で新規保存がないことを示します。中断や故障は通常終了と区別します。joinでも、他の参加者が保存を許可した場合を含め、参加した世代の保存結果を表示します。`saved=unknown` は保存成否を確定できなかったことを示します。共有結果の公開前に待機者だけを中断した場合や、実行担当が突然終了した場合などが該当します。

診断は呼び出しごとに生成し、キャッシュしたstdout/stderrには保存しません。実行担当と待機者はそれぞれ自身の `--verbose` 指定に従い、キー・再利用条件・保存条件・合流可否は変わりません。診断項目にはコマンド、引数、環境変数値、追加キーの生値、子の出力を含めません。パス内の改行や制御文字はエスケープします。接頭辞で子の標準エラーやツールエラーと区別できますが、子が同じ接頭辞を出すことを防ぐ仕組みではありません。

配送は **best effort** です。診断だけの書込失敗、パイプの早期クローズ、読み手の停滞が、実行・共有結果の確定・保存・終了を妨げることはありません。診断は欠落・途切れる場合があり、詰まった読み手への即時到達は保証しません。子の出力転送自体の既存の挙動は変えません。機械処理向けの安定形式ではなく、JSON形式や環境変数による有効化も提供しません。`--clear --verbose` は引数エラーです。削除は従来どおり件数の要約を表示します。

## キーと保存先

環境変数、実行ファイル、入力ファイルが結果に影響する場合は、追加キーまたはrefreshを使ってください。

```sh
cacheexec --ttl 5m --key "$DEPLOY_ENV" -- ./query
```

保存先は両OSとも `$XDG_CACHE_HOME/cacheexec` です。XDGが未設定または空の場合は `$HOME/.cache/cacheexec` を使います。`--cache-dir PATH` で変更できます。ローカルファイルに保存し、完了した結果にはチェックサムを付け、不可分に公開します。キーごとに最新の結果を1件保持します。出力はメモリに蓄えるため、利用可能なメモリに収まる出力量を想定してください。ネットワークファイルシステムでの動作保証は対象外です。

## 終了コードとエラー

| 状況 | 終了コード |
|---|---|
| 子の通常終了 | 子の終了コード（0〜255） |
| シグナルによる中断 | 128 + シグナル番号 |
| ツールエラー | 125（`cacheexec:` 診断付き） |
| 引数エラー | 2 |

結果が存在しない場合は通常のキャッシュミスです。破損やアクセス不能はrefresh時も含めてツール自体のエラーとし、黙ってキャッシュを迂回しません。ツールエラーは標準エラーに `cacheexec:` で始まる診断を出し、**125**で終了します。引数エラーの終了コードは**2**です。子プロセスが通常終了した場合は、その終了コードをそのまま返します（2や125も含みます）。内部エラーとの区別には診断を使ってください。子プロセスがシグナルで終了した場合は、**128 + シグナル番号**を返します。実行後の保存に失敗した場合、子プロセスがすでに終了していることと終了コードを診断に含めます。その場合もコマンドを再実行しません。

## 同時実行と中断

同じキーへの同時呼び出しは、1つの実行を共有します。`--refresh` や、TTL・終了コードの選択条件が異なる呼び出しも合流します。実行担当には出力を随時転送し、待機者には完了後に標準出力・標準エラーの全内容と終了結果を返します。待機者自身の条件がその終了コードを除外していても、今回の実行結果は受け取れます。参加者のうち誰かがその通常終了コードの保存を許可していれば、後続の条件を満たす呼び出し向けに保存します。全員が保存を許可しない場合は、既存の待機者のためだけに一時保持します。各待機者は自分が参加した実行世代を保持するため、後の実行に結果を上書きされません。異なるキーは独立して実行します。進行中のrefreshは、以前の保存結果より優先されます。

子の終了とstdout/stderrの収集後、共有結果の公開を確定します。実行担当への出力配送が終わるのを待たずに保存・公開するため、その読み手が停止しても待機者は結果を受け取れます。配送先の切断などによるエラーは、その呼び出しだけを125にし、共有結果や保存結果を取り消しません。

公開の確定前に実行担当へ届いたSIGINT/SIGTERMは、共有実行を中断します。子の実行・出力収集中は子プロセスグループへ転送し、全参加者に128 + シグナル番号を返し、結果は保存しません。子がシグナルを処理して通常終了した場合も同じです。

公開の確定後は、実行担当へのシグナルもその呼び出しの配送だけを128 + シグナル番号で中断し、待機者と保存結果は維持します。確定とシグナルが競合した場合は、確定点で前後を判定します。その後の公開処理でストレージエラーが発生した場合は、共有実行の失敗として扱います。待機者だけに送られたシグナルは、その待機だけを128 + シグナル番号で終了させ、共有実行は継続します。完了済み結果の再生中や、出力の受け取り側が読み取りを止めた場合にも適用します。出力の配送を中断すると、その呼び出しの出力や診断が途中で切れることがあります。子プロセスのタイムアウトは設けません。これらのシグナルを無視する子は実行を続ける場合があります。子プロセスグループから離れた子孫へのシグナル伝播は保証しません。

実行担当が共有結果を公開する前に突然終了した場合（SIGKILLを含む）、待機者はツールエラーを返し、再試行しません。公開後の突然終了では共有結果と保存結果は維持します。実行担当の識別にはカーネルのロックを使い、PIDの再利用を確認する方式には依存しません。後続の呼び出しは新しい実行を開始できます。ただし、SIGKILLで親を失った子はまだ動いている可能性があり、自動では終了させません。共有用の一時結果は完了時にファイル名を削除しますが、既存の待機者は開いたファイル記述子を通じて引き続きアクセスできます。取り残された実行マーカーは、次の同一キーの呼び出しが回収します。呼び出しの実行中にロックファイルを削除・置換しないでください。ファイルシステムやロックの故障は明示的なエラーになります。削除には以下のオプションを使ってください。

## 破損した結果からの復旧

破損エラーには対象の `.result` ファイルのパスと復旧手順を表示します。そのキャッシュディレクトリを使うすべてのcacheexec呼び出しを停止し、表示された `.result` ファイルだけを削除してから元のコマンドを再実行してください。`.lock` と `.active` ファイルは残してください。`--refresh` と `--clear` のどちらも、破損した結果を黙って削除しません。

## 明示的なキャッシュ削除

```sh
cacheexec --cache-dir ./cache --clear
cacheexec --cache-dir ./cache --clear --older-than 24h
```

削除時にはコマンドやTTLを指定しません。`--clear` は使用中でない再利用可能な結果をすべて削除します。`--older-than` を付けると、完了からの経過時間が指定期間を厳密に超えた結果だけを削除します。境界と一致する結果や未来の完了時刻を持つ結果は残します。この期間は読み手のTTLとは独立しています。走査は1回だけなので、同時に作成されたキーは次回の削除まで残る場合があります。自動削除やバックグラウンドサービスはありません。

結果の要約には、削除した結果数、回収した実行マーカー数、使用中でスキップしたキー数、失敗数を表示します。使用中のキーのスキップは成功扱いです。必要に応じて後で再度削除してください。実行中のデータと待機者へ未配送の実行世代は、refreshや新しい実行をまたいでも保護します。保存先ディレクトリが存在しなければ、作成せずに成功します。破損、権限不足、削除失敗は診断と途中までの件数を示し、125で終了します。成功した削除は取り消しません。破損した結果は調査のため残します。同時呼び出しが別々のロックinodeを使うことを防ぐため、固定の `.lock` ファイルは意図的に残します。保存用の匿名一時ファイルや認識できないファイルも、所有者を安全に特定できないため残します。こうした残存ファイルを手動で削除する場合は、すべてのcacheexec呼び出しが停止してから行ってください。呼び出しの実行中にキャッシュディレクトリを再帰的に削除しないでください。

## 開発

`rust-toolchain.toml` でRust 1.98.0を固定しています。macOS/LinuxのCIでも同じチェックを実行します。

```sh
cargo fmt --check
cargo clippy --locked --all-targets -- -D warnings
cargo test --locked
```
